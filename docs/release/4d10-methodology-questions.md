# 4D.10 methodology question register (for Mike / Jon)

Open questions found while building and accepting 4D.10. Each states what the MVP does **today**; none has been
answered by inventing policy. Changing any of them may need schema, a new rule or a new report version — each is a
PMO / methodology-owner decision.

| #   | Question                                                                                                                                  | Current MVP behaviour                                                                                                                                                                                                                                                                                                     |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Can a Value Change determination (No Value Change Required / Value Change Proposed) be superseded or corrected?                           | Permanent: one per management decision, insert-only, enforced by the database. No correction route exists.                                                                                                                                                                                                                |
| 2   | What should happen after a proposed Value Change is rejected or withdrawn?                                                                | The determination stays "Value Change Proposed"; the review shows the closed Value Change and offers no further action. The database would accept another Value Change citing the same decision, but the review offers no "prepare again" or "re-determine" step — the consultant's only route is an ad hoc Value Change. |
| 3   | Should Draft / Returned recommendations be allowed when a formal review is finalised, or explicitly abandoned / carried forward?          | Allowed (PMO rule: only In Internal Review / Ready to Issue block finalisation). After finalisation the draft/returned recommendation can never progress (the review is read-only); the page says no recommendation was issued. Nothing carries it forward.                                                               |
| 4   | Should dropped **non-financial** outcomes require a "why not carried forward" reason in V1?                                               | Only financial Original Business Case drivers dropped from V1 require a reason; non-financial drops may have one optionally.                                                                                                                                                                                              |
| 5   | Should V2+ driver-level reasons become mandatory in some circumstances (e.g. several drivers move)?                                       | Optional. A Value Change requires its own reason at proposal; driver-level reasons are offered but not required.                                                                                                                                                                                                          |
| 6   | Should management decisions recorded before 4D.10H ever receive retrospective determinations?                                             | Not manufactured. A historical decision with no determination and no Value Change reads "To be determined"; the Overview next action prompts only for the **most recent** decision, and the consultant may record one.                                                                                                    |
| 7   | Should Information Request closure / outstanding evidence create a soft governance acknowledgement at V1 proposal or review finalisation? | Visibility only: outstanding items are shown (Mobilisation, Assurance matters, finalise checklist "not blocking"). No gate and no acknowledgement field.                                                                                                                                                                  |
| 8   | Does Cardaxia require formal separation of duties between recommendation author and internal reviewer?                                    | Not enforced: the pilot auth model cannot distinguish them. The acting user of every submit / return / ready / issue step is recorded (history + audit); the UI says so.                                                                                                                                                  |
| 9   | Confirm the standard Day-1 Information Request item list.                                                                                 | Five starter suggestions offered (Existing Business Case, Business Case financial model, Existing benefits / value-driver model, Programme / project plan, Baseline performance evidence); the consultant chooses any and adds custom items. Not mandatory.                                                               |
| 10  | Future report terminology: Re-Qualification Report → Value Case Definition Report for **new** issues only?                                | Unchanged: the report keeps its issued name "Re-Qualification Report" (renderer and the in-app link to it); everything else in the app says Value Case Definition. A renamed report would be a new versioned renderer.                                                                                                    |
| 11  | Should determinations, internal review history and movement reasons appear in client reports?                                             | Not shown in any issued or new report (renderers unchanged); visible in the app only. Future versioned-renderer work.                                                                                                                                                                                                     |
| 12  | Should the Overview next action prompt for every unsatisfied cadence requirement?                                                         | It prompts "Open the …" only when a requirement is **Due** and no review is open (4D.10I fix: never "no action pending" beside a Due requirement). Upcoming requirements are shown, not prompted.                                                                                                                         |
| 13  | Value Gap after a Value Change but before a review against the new version                                                                | Shown against the version the latest review measured (e.g. "Against Authorised V1 — no formal review against V2 yet"); never recomputed against V2. Confirm this is the intended executive reading.                                                                                                                       |
